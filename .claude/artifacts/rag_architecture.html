DBLP dashboard · Ask

How Ask answers a question

A language model answers questions about the DBLP data by calling four fixed tools over a local index of 8.4 million papers. It never writes SQL and never answers from its own knowledge: every number and paper in an answer comes from a tool result, and the code checks that.

  • 8,423,776 papers
  • 4,263,299 authors
  • 1,540,807 papers with meaning vectors (2024 on)
  • 4 tools
  • 5 model providers

2 · Finding papers

Hybrid search: keywords and meaning together

DBLP holds titles, years, venues and authors only, so a paper is found by its title. Keyword search finds the exact words; semantic search finds titles that mean the same thing in other words.

3 · The agent loop

Each round, and what the code checks

The model decides which tools to call; the loop runs them and decides what the model is allowed to send back.

Answers only from the data
An answer that used no tool is accepted only if it is the decline message. Mistral once answered with invented counts and no tool call; this check catches that.
Declines what isn't about DBLP
Concept explanations, general knowledge, code requests and "ignore your instructions" get a fixed reply that suggests a question the data can answer.
Made-up citations removed
Every paper a tool returns gets a ref (P1, P2, …). Refs the model invents are dropped from the answer and from the sources list.
Tool calls written as text
Small local models write {"name": "topic_stats", …} as plain text. A reply that is only such calls is run as real tool calls.
Citation formats
GPT-OSS writes 【P1】 and sometimes puts an invisible zero-width space inside the brackets; both are recognised.
Limits
Each tool call stops after 30 seconds; rate-limited providers are retried up to three times; Stop and closing the tab cancel the work.
